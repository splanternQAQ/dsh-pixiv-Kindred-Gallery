# Pixiv 知心画廊（dsh-pixiv-Kindred-Gallery）

DeepSeek Harness 插件：**跑一轮 / 评分 / 作品库 / 口味画像**。它自己不算图——搜图、看图、下载都交给「刷Pixiv」（dsh-pixiv-scroll），画廊负责把结果摆成卡片、让你打分、学你的口味。

作者：春灯笼　·　GitHub：[@splanternQAQ](https://github.com/splanternQAQ)

## 安装（一条命令）

在 PowerShell 里粘这一行：

```powershell
powershell -ExecutionPolicy Bypass -c "irm https://github.com/splanternQAQ/dsh-pixiv-Kindred-Gallery/raw/main/install.ps1 | iex"
```

脚本会：下载仓库 zip → 放到 `D:/Deepseek_Plugins/dsh-pixiv-Kindred-Gallery` → 写进 profile 的 `dependencies` 与 `dsh.profile.bundles` → 在 `node_modules` 建联接（旧目录自动备份）。

**装完重启 DSH**，标签栏就会出现「知心画廊」。

接着装它的搭档：打开「知心画廊」→ 设置 → 下载相关顶部点 **一键安装**（拉 1.1.14 的刷Pixiv）→ 再重启一次 → 到「刷Pixiv」登录 pixiv 账号（token 或账号密码）。

> 只装画廊也能开页面、改设置、看历史卡片；但**跑不出新图、下载/点头不可用**——那些能力属于刷Pixiv。
>
> npm 包（`dsh plugin add dsh-pixiv-kindred-gallery`）还没发布，目前请用上面这条命令。

### 1.0.2 —— 网络自动换路与连接诊断

这一版解决「明明能直连，却因为一个没在用的代理而连不上 pixiv」：以前只要注册表里留着代理地址，哪怕代理软件没开、端口是空的，也会一直拿它去连，失败就整轮抓不了图。

- **自动换路**：请求按「直连 → 环境变量代理 → 注册表代理」依次尝试，只在建连阶段失败（连接被拒、连不上、握手失败）时换下一条；业务错误（429 限流等）原样抛出，不会因为被限流就偷偷换 IP。
- **代理开关与端口分离**：系统代理开关关着但端口仍在监听（TUN 模式、只关了开关没退软件）时仍然可用；端口没人听、开关也关着就不再尝试它。走通过的路由缓存 60 秒，死掉的代理冷却 120 秒。
- **直连优先**：能直连就先直连；直连实测被拒后 5 分钟内不再排在前面。直连只是慢（探路 6 秒超时）时会用完整超时再试一次，不会因为慢就武断换路。
- **界面说清走哪条路**：顶部信号灯现在分「pixiv 直连 · N ms」「pixiv 经代理 · N ms」「pixiv 连接超时」「连不上 pixiv」四种，悬停还能看到换路轨迹（如「直连（请求超时）→ http://127.0.0.1:7890（成功）」）。
- **慢轮诊断更具体**：超过 35 秒的轮次，弹窗顶部把最耗时的那一项单独放大（含占总时长百分比），并按实际路由给建议 —— 走代理就建议换节点，直连就建议查本地网络；本地筛选项会明确说明与网络无关。
- **运行测试与跑一轮**：设置页「画廊运行测试」的 pixiv 步骤、跑一轮的进行中提示、每轮总结都会写明访问 pixiv 的方式、预检耗时与接口延迟。
- 修复预检里「代理」一栏永远显示为直连的问题（此前读错了字段类型）。

### 1.0.1 —— 作品根搬进画廊自己的目录

这一版处理的是「作品库显示 0 件」「明明下过却当成没下过」这一类问题，根子都在路径上：作品库原先去读刷Pixiv 的 `all_works`，而那个目录可能根本不存在；画廊自己下载的作品又落在另一处，两边对不上。

- **作品根独立**：新增 `setGalleryHome()`，插件装上就在自己的家目录建好 `Download`；作品库、原图下载、删除、打包、复制全部走这里，不再读刷Pixiv 插件的 `all_works`。两边从此各自为政：刷Pixiv 跑的作品在它自己的目录，画廊的在画廊的目录。
- **多级目录**：作品根按 `{kind}/{artist}/{title}_{id}` 分层时，作品库现在会递归扫描；以前只认一层，深层作品会被漏掉，「已下载」的判断也会失效从而重复下载。
- **空库不再拖垮整库**：目录不存在时返回空列表，不再因为一次 `readdir` 抛错就把整库显示成 0 件。
- **改名 / 删除 / 打标签**：新增内部 `workPathOf()`，深层目录里也能按作品名定位到真实路径。
- **定时下载**：15 分钟一次的「补下漏掉的评分作品」此前一直报 `queueAutoDownload is not defined`（函数在 `makeApi` 闭包内，定时器在闭包外），现在跨作用域取到它了。
- 数据位置说明同步：作品库与原图都在 `~/.dsh/dsh-pixiv-Kindred-Gallery/Download/illust/{画师}/{标题}_{id}`。

### 严格度决定引擎（0.7.70 起）
「跑一轮预设」里不再单独选「执行方式」，只留「严格度」，由它决定走 AI 还是快跑：

- **严格**：起一个刷Pixiv 的子代理，逐张看图精挑，宁缺毋滥（慢，但会审美判断）。
- **平衡**：画廊自己按预设快跑；候选不够时只放宽一档，尽量凑满。
- **数量优先**：同样走快跑，一路放宽筛选直到凑满。

快跑不碰刷Pixiv 的进程，也不需要恢复配置：关注时间线 + 喜好标签搜索（最多 4 个词 × 2 页，8 路并发）→ 逐件补详情（6 路并发）→ 本地按分级/收藏/浏览/点赞/加权/命中/作者配额过滤 → 写 picks/<round>/candidates.json + 缩略图。0.7.60 起**不再自动下载原图**：新卡片只保留缩略图，原图要手动下载，或等评分入库后命中自动下载条件。快跑的产物格式和 AI 模式完全一致，作品库/评分/下载都一样用。

### 全局去重（0.6.2）
「新的卡片检查」不再受预设开关控制，改成**全局强制**：

- 每收集到一张（进轮次、被打开、被下载），立刻把它的 pixiv id 记进 `gallery.json` 的 `collectedIds`；
- 之后不管是哪个预设、哪种引擎，只要这个 id 出现过，就不会再推给你——不需要它先被评分/收藏/入库；
- 启动时会扫一遍历史轮次与作品目录，把以前收集过的补登记（本次补了 177 件）；
